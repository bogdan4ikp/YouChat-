# YouChat — серверная версия

Мессенджер YouChat: аккаунты, общая база, группы, заявки на вступление, поиск людей по
`@username` и доставка сообщений в реальном времени. Вход — только через Яндекс ID:
паролей и отдельной регистрации нет. Клиент лежит в `aurora-src` (внутренняя папка
с прежним именем), данные — на сервере.

## Что внутри

- `server/server.js` — сервер на Node.js без внешних зависимостей
  (`node:http`, `node:sqlite`, `node:crypto`), плюс OAuth Яндекс ID.
- `aurora-src/` — клиент: HTML, CSS и JS-модули (`net.js` — сетевой слой и экран входа).
- `YouChat.html` — автономная сборка клиента (работает без сервера в локальном режиме).
- `server/data/` — создаётся автоматически: `youchat.db` (SQLite) и `uploads/` (медиа).

## Требования

Node.js 22.5+ (используется встроенный `node:sqlite`). Проверено на Node 26.
Внешние пакеты и `npm install` не нужны.

## Запуск

```bash
node server/server.js
```

По умолчанию порт `8080`. Настройки через переменные окружения:

```bash
PORT=8080 HOST=0.0.0.0 node server/server.js
```

Откройте `http://localhost:8080` — появится экран входа YouChat с единственной кнопкой
**«Войти через Яндекс ID»** (нужна настройка, см. ниже). Паролей и формы регистрации нет:
адреса `/api/auth/register` и `/api/auth/login` отвечают 403, аккаунт создаётся только
после успешной авторизации в Яндексе. Люди находят друг друга по `@username` кнопкой
«Найти людей».

## Как удалить все аккаунты

Остановите сервер и удалите папку с данными:

```bash
rm -rf server/data        # Windows: Remove-Item -Recurse -Force server\data
node server/server.js     # база и uploads создадутся заново, аккаунтов нет
```

После этого любой вход начинается с экрана «Войти через Яндекс ID». На сервере под
nginx путь к папке тот же — `server/data/youchat.db` и `server/data/uploads/`.

## Вход через Яндекс ID

1. Создайте приложение на <https://oauth.yandex.ru/client/new>:
   - платформа «Веб-сервисы»;
   - Redirect URI: `https://ваш-домен/api/auth/yandex/callback`
     (для локальной проверки — `http://localhost:8080/api/auth/yandex/callback`);
   - доступ к данным: «Логин, имя, фамилия, портрет» и, по желанию, «E-mail».
2. Пропишите ключи. Удобнее всего — в файле `server/.env` (сервер читает его сам,
   при старте; переменные окружения имеют приоритет):

```ini
PORT=8080
HOST=0.0.0.0
PUBLIC_URL=https://ваш-домен
YANDEX_CLIENT_ID=ваш_client_id
YANDEX_CLIENT_SECRET=ваш_client_secret
```

Шаблон лежит рядом: `server/.env.example`. Файл `server/.env` добавлен в `.gitignore` —
секрет не попадёт в репозиторий. Если секрет всё же утёк, перевыпустите его кнопкой
обновления в консоли Яндекса.

Либо передайте те же значения переменными окружения в командной строке:

```bash
YANDEX_CLIENT_ID=ваш_id \
YANDEX_CLIENT_SECRET=ваш_секрет \
PUBLIC_URL=https://ваш-домен \
node server/server.js
```

`PUBLIC_URL` должен совпадать с адресом, на котором открыт сайт: из него собирается
`redirect_uri`, и Яндекс требует точного совпадения с настройками приложения. Для локального
запуска `PUBLIC_URL=http://localhost:8080`.

Если ключи не заданы, кнопка Яндекс ID остаётся, но при нажатии подсказывает, что вход через
Яндекс не настроен, и предлагает вход по логину и паролю. Сервер пишет состояние входа при
старте: `Вход через Яндекс ID: включён / не настроен`.

Как это устроено: `GET /api/auth/yandex/start` → редирект на `oauth.yandex.ru` (с защитным
`state` в HttpOnly-cookie), `GET /api/auth/yandex/callback` меняет код на токен, забирает
профиль из `login.yandex.ru/info`, создаёт или находит пользователя по `yandex_id` и выдаёт
обычную сессию. Пароль таким пользователям не нужен — в базе лежит случайный хеш.

### Онбординг после первого входа

Новый пользователь из Яндекса создаётся с флагом `onboarded = 0`: имя, фото и (если
Яндекс отдал) дата рождения уже подставлены, а короткий адрес сгенерирован автоматически
из имени — латиницей, с цифрами, с проверкой на занятость. Приложение открывает экран
«Давайте знакомиться»: можно поправить имя, выбрать `@username` (уникальность проверяет
`GET /api/username?u=...`), заполнить «О себе» и дату рождения, поставить своё фото и
баннер. Сохранение — `PATCH /api/profile` с `complete: true`; после этого флаг становится
`1`, и человек попадает в мессенджер. При повторном входе онбординг не показывается:
`profile.onboarded` в `/api/state` уже `true`. Регистрация по паролю сразу считается
завершённой — имя и адрес спрашиваются на форме.

## Как это работает

- Регистрация и вход по `@username` + пароль: пароль хранится как scrypt-хеш с солью,
  сессия — HttpOnly-cookie на 30 дней.
- Любое действие (сообщение, реакция, закрепление, роль, заявка, профиль) идёт через
  REST API `/api/...`; сервер проверяет участие в беседе и права роли.
- Реальное время: каждое изменение рассылается подключённым участникам через SSE
  (`/api/stream`), клиент перечитывает состояние. Поэтому сообщения появляются у всех
  без перезагрузки, а статус «в сети» считается по открытым потокам.
- Непрочитанные считаются по `last_read` каждого участника.
- Группы: владелец, админы с правами, заявки на вступление, передача владения,
  исключение участников, журнал действий.
- Ссылки `https://ваш-домен/g/<handle>` открывают карточку вступления, `/u/<username>` —
  поиск человека. Если группа закрыта, создаётся заявка.
- Медиа: изображения и видео загружаются на сервер (`POST /api/upload`) и отдаются из
  `/uploads/...`; в сообщениях хранятся только ссылки.

## Ветка «без сервера»

Если открыть `YouChat.html` двойным щелчком (или если сервер недоступен), приложение
переходит в локальный режим: данные остаются в браузере. На экране входа есть кнопка
«Продолжить без сервера (локально)».

## Развёртывание на своём домене

1. Запустите сервер под systemd или pm2, например:

```ini
[Unit]
Description=YouChat messenger
After=network.target

[Service]
WorkingDirectory=/srv/youchat
ExecStart=/usr/bin/node server/server.js
Environment=PORT=8080
Environment=HOST=127.0.0.1
Environment=PUBLIC_URL=https://example.com
Environment=YANDEX_CLIENT_ID=...
Environment=YANDEX_CLIENT_SECRET=...
Restart=always
User=youchat

[Install]
WantedBy=multi-user.target
```

2. Поставьте nginx перед сервером и обязательно включите HTTPS (Let's Encrypt).
   Для SSE нужен отключённый буферинг:

```nginx
server {
    listen 443 ssl http2;
    server_name example.com;

    client_max_body_size 150m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/stream {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 24h;
    }
}
```

Сервер сам выставляет `Secure` на cookie, если видит `X-Forwarded-Proto: https`.

3. Резервные копии: остановите сервер и скопируйте `server/data/` целиком
   (`youchat.db`, `youchat.db-wal`, `uploads/`). Этого достаточно, чтобы восстановить всё.

## Ограничения текущей версии

- Одна инсталляция = один сервер и одна SQLite-база. Для больших нагрузок нужен
  переход на PostgreSQL и горизонтальное масштабирование — это отдельная задача.
- Нет восстановления пароля для входа по логину; для Яндекс ID пароль не нужен.
- Шифрования end-to-end нет: сервер видит сообщения (как в обычных веб-мессенджерах).
- Голосовые и видео-кружки до 1 минуты, файлы до 140 МБ, текст до 4000 символов.
- Статус «в сети» приблизительный: считается по открытому SSE-соединению.
